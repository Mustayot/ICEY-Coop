# 游戏联机体检

双方安装同一份完整安装包后，正常启动游戏。主菜单及游戏中按 **F8** 打开或关闭体检面板。面板约每秒读取一次状态，**不会暂停游戏或自动操控角色**。

面板可以看到：

- 当前主机/客机角色、会话阶段和本机关卡。
- 关键补丁及联机存档保护是否生效。
- P1/P2 的原生绑定或客机镜像是否存在；主机是否共享了本应独立的角色数据。
- 双方当前血量与能量读数；客机读数是主机镜像。
- 客机发送的输入序号、主机接受序号、有效回执序号，以及回执是否过期。
- 客机有效快照的接收量与时效；新快照是否正在等待可靠事件追平。
- 本次游戏运行最近一条已记录的错误，并明确标注为历史错误。

点击 **导出当前报告**，报告写到此游戏目录的 `BepInEx/icey-coop/diagnostics/health-*.json`。不会覆盖旧报告，不上传文件，不包含重连凭证字段。报告有捕获时间、运行编号及实际构建编号，分析时不要把上次运行的旧报告当成当前状态。双方各导出一份，结合双方同次运行的 `BepInEx/icey-coop/logs/icey-coop-*.jsonl` 定位问题。

## 如何理解结果

| 状态 | 含义 |
| --- | --- |
| Pass | 这一项已经取得符合条件的运行样本，不表示整个游戏已通过验收 |
| Waiting | 尚未联机、正在加载或还没有足够样本；不把它当故障，也不把它当通过 |
| Warning | 需要关注，例如通道超过 3 秒未更新、远端脱离或角色绑定缺失 |
| Failure | 已确认不满足关键条件，例如保护未启用、采样器不可用或通道长期失效 |
| Info | 补充事实或验收边界；错误历史不代表当前仍在发生 |

正常网络中发送序号可能比回执序号领先，因为有输入仍在途中；只要有效回执持续更新，不会因此误报输入失败。重复、过期或无效回执不能刷亮新鲜度。

主机没有“接收主机快照”的通道，其相应项目显示 Waiting；客机没有主机原生属性，这些读数来自呈现镜像。未攻击或没有取得实际 HP 变化时，体检不会宣称伤害、技能、独立扣血已经验证。绑定存在也不等于真人按键已正确执行。

## 本版修复

1. 主机不再把丢弃的重复或无效输入回报为已接受；客机读取真实回执并检查槽位、序号和结果。
2. 客机拒绝迟到的旧快照、重复分片及早于本次关卡基线的样本，避免它们回写角色位置、血量和动画。
3. 快照与可靠事件先后到达时，保持可靠事件游标和实体版本一致；不再把带实体的伤害等事件一律当版本 0，避免中途加入或连续伤害后出现事件断链。

协议仍为 4。UDP 比可靠事件先到时，该视觉样本会延后，依靠后续周期快照刷新；事件积压时体检会显示差值，并按快照时效报警。没有改写怪物 AI、伤害数值、原生技能或场景刷怪规则来掩盖同步问题。

## 保留的边界

本机双副本测试不等于真人两台电脑跨网验收；完整主线、全部 Boss、跳跃隔离及 P2 大招仍须实际玩法样本确认。当前快照协议没有独立 session/epoch 字段，基线的主机时钟与事件屏障覆盖同一进程内的关卡切换，不承诺能绝对识别跨主机进程重启残留的所有旧 UDP 包。

双方必须更新同一构建，不能只换一个 DLL。升级保留合作存档，但既有兼容门禁可能拒绝恢复不同构建的旧合作档；请保留安装器备份和旧存档。本版不绕过该门禁，也不修改 Steam 单人存档。
